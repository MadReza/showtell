How they did it

Every part Showtell needs has been solved well by someone. Nobody solved the part we care about most: a persistent target that gets screenshots. This page takes the six parts one at a time.

1 · Finding the session

localvoxtral follows your focus. We want a pin.

This is why localvoxtral didn't fit you. It decides the target at the moment you start talking, from whatever is in front. A pinned target needs none of that chain.

localvoxtral read

A Claude Code plugin's hooks (SessionStart, UserPromptSubmit, Stop, Notification…) send each session's id, cwd, tty, claude_pid and HERDR_PANE_ID to a local socket. The app keeps a registry and expires sessions after 4 h or when the pid dies.

Borrow: its "send that to X" path, which writes to a session's own pane without any focus check, and re-checks before each write that the pane still runs that session.

ClaudeSessionRegistry.swift · ClaudeSessionJoinResolver+Herdr.swift:70 · +AddressedSend.swift:62

herdr itself read · live

herdr agent list already returns every Claude pane with its session id, folder, title and status (idle · working · blocked · done). No plugin needed: herdr's own hook reports the id.

Borrow: use it directly for the session picker. Subscribe to pane.agent_status_changed, pane.moved and pane.closed to keep the pin valid.

herdr socket ~/.config/herdr/herdr.sock · agent.list · events.subscribe

3 · Listening live

Three ways to show words while you talk

localvoxtral read

A helper process runs Voxtral Mini 4B (≈3.5 GB) behind a WebSocket shaped like OpenAI's Realtime API. It only ever appends words, so the overlay never has to erase.

Take: the append-only protocol, so engines are swappable.

FluidVoice read · GPL

Two recognisers: a fast one for the live preview, and a second one with custom-word boosting for the final text.

Take: the preview/final split (re-implement; GPL).

VoiceInk read · GPL

FluidAudio's true streaming Parakeet with partial results, or re-running a batch model and committing words once two passes agree.

Take: "commit when stable" for the overlay.

Handy (33k★, MIT, Tauri + Rust) mostly records then transcribes; HN likes it because it does one job, is small, and needs no account. Its fuzzy word fix is easy to copy.

4 · Fixing your words

The best results stack a model-level boost and a text-level fix

ToolWhere the fix happensHow
FluidAudio readin the speech modelA small extra model spots your terms in the audio and swaps in the right spelling, with aliases ("herder" → herdr). Tested to ≈230 terms.
localvoxtral readbefore + during cleanupTerms from the repo's file names and .github/dictation.md. Exact matches fixed directly; sound-alikes go to a local 4B LLM as candidates.
VoiceInk readafterLLM prompt with your vocabulary, a replace list, and "auto-learn" from your later edits. No model-level boost locally.
Handy readafterFuzzy match (Levenshtein + Soundex) against your list.

For Showtell: because we know the pinned session's folder, we can load that repo's .github/dictation.md and file names as boost terms automatically, and switch them when you pin a different session.

6 · Overlay and hotkeys

Everyone converged on the same window type

A non-activating floating panel (NSPanel, .nonactivatingPanel, all Spaces) shows the words without taking focus from the app you're looking at. Hotkeys: Carbon RegisterEventHotKey for normal shortcuts (no extra permission), an event tap only for modifier-only push-to-talk (needs Accessibility). localvoxtral registers Tab/arrow keys only while the overlay is up, a nice trick for choosing things mid-dictation.
