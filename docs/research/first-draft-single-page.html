Research · 10 Oct 2026

Showtell

Talk and take screenshots while you look at an app. The narration and screenshots go into the Claude Code terminal session you choose, with each screenshot where you took it, and you never switch to the terminal.

Verdict

Nobody has built this exact tool.

Checked again with stars and HN: popular projects (Handy 33k★, herdr 43k★, voicemode 1.4k★) each own one part. The few that combine parts are small and new: SnippAI, localvoxtral, Deiko, MarkuprPlus.

Hardest part

Delivery, not dictation.

Speech-to-text is a solved problem. The hard part is getting text with images into a Claude Code session that is already running.

Best base to build on (revised)

Extend localvoxtral.

Swift, MIT, built for coding agents. It already streams local voice, handles custom words and sends to herdr and iTerm2 sessions. Missing: screenshots. (Was: fork OpenSuperWhisper.)

1 · The idea in one picture

Capture → align → correct → deliver

The three things you already do by hand (dictate, screenshot, paste) become one recording. At the end it goes to the terminal you picked, not to whichever window is in front.

2 · Screenshots in the right place

Timestamps decide where each image goes

The local speech engines give a timestamp for every word (whisper.cpp WhisperTimings, FluidAudio/Parakeet token timings). Each screenshot is inserted at the nearest sentence boundary to the moment you took it, so it lands at the start, in the middle or at the end exactly as you took it.

What people complain about (HN threads)

"Five steps, dozens of times a day." Screenshot → save → alt-tab → drag → type → enter. Every tool above was built because of this.
"This one" is ambiguous. Words can't say which of nine buttons you mean. People fix it by pointing while talking (Deiko), drawing arrows (ShellShot) or attaching selectors (react-grab).
Jargon gets mis-heard. Custom dictionaries are the most requested feature. Tricks: vocabulary from repo files (localvoxtral), or a screenshot of the window so the LLM gets spellings right (FreeFlow).
Native /voice is weak. About 500 ms of lag drops the first words, it only works while the terminal is focused, and there are no custom words. People prefer a dictation tool that works system-wide.
Only iTerm2 is supported. Every tool that types into a terminal does iTerm2 (sometimes Terminal.app) and nothing else. None supports herdr except localvoxtral (text only).
Local over cloud. Strong preference for on-device models (Parakeet, Whisper). Tools that send telemetry get called out.
Ideas to borrow
  • localvoxtral: word list from repo file names + a .github/dictation.md per repo; send to a session by speaking its name ("send that to payments").
  • MarkuprPlus / Deiko: one screenshot + its piece of narration as the basic unit. Deiko crops to what you were pointing at.
  • ShellShot: a session picker over every live Claude Code session, plus arrows drawn on the screenshot.
  • Quick Entry / Codex Appshots: the overlay design. Appshots also captures the window's off-screen text along with the image.

What's still open: several screenshots kept in order with live narration, delivered to a session you pick in herdr and iTerm2 without focusing it, with custom words. Nobody has all of that. The biggest risk is Anthropic letting Quick Entry target Claude Code sessions.

Rule 1

Each screenshot path has to arrive as its own bracketed paste. Inside a sentence it stays plain text.

Rule 2

Pause after each image until its [Image #N] chip appears (about 0.8 s worked), otherwise the images jump to the end. All three terminals let us read the screen back to check.

Finding sessions

~/.claude/sessions/<pid>.json gives cwd, name and idle/busy status, plus the tmux pane id. The pid's tty matches an iTerm2 session's tty, and herdr agent list maps panes to sessionIds.

Decision after testing all four paths

Primary: A, pasting into the pane (herdr and iTerm2 adapters). The message shows up in your prompt box like something you typed, with real [Image #N]s, and you can even look it over before it's sent. The cost is pausing about 0.8 s per image.

Robust option: D, an inbox tool with a pasted nudge. Showtell queues the message in its MCP server and pastes one short line ("call inbox_next"). There's no image timing to manage and the images arrive as real image blocks. It needs a one-time MCP setup in ~/.claude.json, and the message shows up as a tool result rather than as your own prompt.

Out for now: C (channels are off for your Team org unless an admin enables channelsEnabled). B only as a text nudge, and only if you set crossSessionInbound: "accept" in your user settings (untested).

6 · The Lavish pattern you mentioned

Queue the message, let the agent pick it up

lavish-axi doesn't push into Claude. The browser adds feedback to a queue that survives restarts, and the agent collects it with lavish-axi poll. Showtell could do the same thing as a fallback: an "outbox" per session that is never lost, even when the terminal is busy.

Why streaming matters

With live transcription, a screenshot just goes where the text has reached at that moment. Section 2's timestamp alignment isn't needed. Hotkey → [Image #n] chip in the overlay → keep talking.

Costs of this route

It's a large codebase (~1,600 files). The 4B model is heavier than Parakeet. A fork means keeping up with an active upstream, so the better path is small PRs upstream (the repo has CLAUDE.md/AGENTS.md and invites contributions).
