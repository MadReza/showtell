What people complain about (HN threads)

"Five steps, dozens of times a day." Screenshot → save → alt-tab → drag → type → enter. Every tool above was built because of this.
"This one" is ambiguous. Words can't say which of nine buttons you mean. People fix it by pointing while talking (Deiko), drawing arrows (ShellShot) or attaching selectors (react-grab).
Jargon gets mis-heard. Custom dictionaries are the most requested feature. Tricks: vocabulary from repo files (localvoxtral), or a screenshot of the window so the LLM gets spellings right (FreeFlow).
Native /voice is weak. About 500 ms of lag drops the first words, it only works while the terminal is focused, and there are no custom words. People prefer a dictation tool that works system-wide.
Only iTerm2 is supported. Every tool that types into a terminal does iTerm2 (sometimes Terminal.app) and nothing else. None supports herdr except localvoxtral (text only).
Local over cloud. Strong preference for on-device models (Parakeet, Whisper). Tools that send telemetry get called out.
Ideas to borrow
  • localvoxtral: word list from repo file names + a .github/dictation.md per repo; send to a session by speaking its name ("send that to payments").
  • MarkuprPlus / Deiko: one screenshot + its piece of narration as the basic unit. Deiko crops to what you were pointing at.
  • ShellShot: a session picker over every live Claude Code session, plus arrows drawn on the screenshot.
  • Quick Entry / Codex Appshots: the overlay design. Appshots also captures the window's off-screen text along with the image.

What's still open: several screenshots kept in order with live narration, delivered to a session you pick in herdr and iTerm2 without focusing it, with custom words. Nobody has all of that. The biggest risk is Anthropic letting Quick Entry target Claude Code sessions.
