Getting it into Claude Code

Short answer: paste into the herdr pane through herdr's socket, one piece at a time. Screenshot paths become real [Image #N] chips, and it works even while Claude is busy.

Rule 1

Each screenshot path has to arrive as its own bracketed paste. Inside a sentence it stays plain text.

Rule 2

Pause after each image until its [Image #N] chip appears (about 0.8 s worked), otherwise the images jump to the end. All three terminals let us read the screen back to check.

Finding sessions

~/.claude/sessions/<pid>.json gives cwd, name and idle/busy status, plus the tmux pane id. The pid's tty matches an iTerm2 session's tty, and herdr agent list maps panes to sessionIds.

Decision

Primary: pane paste through herdr's socket (pane.send_input). Your message shows up in the prompt like something you typed, with real chips, and queues if Claude is busy.

Backup: D, an MCP inbox tool that returns the images as image blocks, nudged by a one-line paste. Only if chips ever turn out unreliable.

Out: C (channels are off for your Team org); B (inbox socket) drops images and needs an approval click in bypass mode.

The Lavish pattern you mentioned

Queue the message, deliver when the session can take it

lavish-axi doesn't push into Claude. The browser adds feedback to a queue that survives restarts, and the agent collects it with lavish-axi poll. Showtell could do the same thing as a fallback: an "outbox" per session that is never lost, even when the terminal is busy.
